EDNS Client Subnet (ECS) module
================================

This module adds support for the *EDNS Client Subnet* (ECS, RFC 7871) option in
outbound queries generated by Knot Resolver.  When enabled, the resolver will
append an OPT option with code 8 that carries the network prefix of the
original client, allowing authoritative servers and upstream resolvers to
provide topology–aware answers.

Behaviour
---------
1. For each DNS request arriving to Knot Resolver, the source IP address is
   extracted.
2. When the resolver later constructs an upstream query, the module’s
   *checkout* hook injects a single ECS option into the OPT RR.
3. The option contains:

   * Address family – 1 for IPv4, 2 for IPv6.
   * Source-prefix-length – configurable (defaults: ``/24`` for IPv4 and
     ``/56`` for IPv6 as recommended by RFC 7871).
   * Scope-prefix-length – always 0 (let upstream decide on scope).
   * Network address – the client IP truncated to the configured prefix
     (remaining bits are zeroed).

4. Any pre-existing ECS option on the packet is removed to avoid duplicates.

Configuration
-------------
The module is built and installed automatically with the rest of Knot Resolver.
Enable it from Lua configuration:

.. code-block:: lua

   modules = {
     'ecs',          -- enable ECS with default prefix lengths
   }

Optional run-time properties allow to fine-tune prefix lengths:

* ``prefix4=<bits>`` – set IPv4 prefix length (0–32).
* ``prefix6=<bits>`` – set IPv6 prefix length (0–128).

Example (use /32 and /64):

.. code-block:: lua

   modules.load('ecs')
   modules.set('ecs', 'prefix4', '32')
   modules.set('ecs', 'prefix6', '64')

Testing
-------
A minimal unit-test is provided in ``tests/unit`` and basic integration tests can
be run with Deckard:

.. code-block:: bash

   meson test -C build --suite integration ecs

Limitations
-----------
* The current implementation only adds ECS to *queries*.  Incoming ECS options
  from upstream answers are ignored and responses are cached normally.  This is
  usually acceptable because authoritative servers should return the same
  answer for the whole *scope* they declare.
* Cache-key segmentation by ECS is not included; advanced users deploying a
  shared resolver in front of diverse networks should evaluate the impact.

Reference
---------
